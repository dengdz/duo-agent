# 应用 duo-agent 文档规范

文档规则活在 [docs/index.md](../../../docs/index.md) 的导航结构与各篇自身。本技能覆盖放置、结构分类、语料审计与验证。**它是指导，不是脚本**；编辑判断（该保留什么、删什么）用 [duo-trim-cot-leakage](../duo-trim-cot-leakage/SKILL.md)；**永远不要把长度本身当缺陷**。

## 事实来源（读原文，不要转述）

- [docs/index.md](../../../docs/index.md) —— 五章节导航：01 入门 / 02 指南 / 03 高级 / 04 架构 / 05 参考。
- [README.md](../../../README.md) —— 门面印象与入口；与 docs/ 是"摘要 → 详情"关系，不承载细节。
- [SDK_DESIGN.md](../../../SDK_DESIGN.md) / [HANDOFF.md](../../../HANDOFF.md) —— 历史设计文档与决策记录；活跃文档不重复其内容，链接过去。
- [docs/05-reference/limitations.md](../../../docs/05-reference/limitations.md) —— 已知限制的唯一清单。任何"暂不可用/未接线"的表述以它为准。

## 先结构，后文字

对范围内每篇文档按此顺序检查（HANDOFF.md 等历史记录不适用结构改造）：

1. **定位**：文档在 docs/ 树中的位置是否匹配其主题？入口（index.md 导航表）是否有它的链接？
2. **详略分层**：本篇保留自身主题的完整细节；直接子主题按"目的 + 职责 + 高层行为"摘要并链接到拥有它的篇章。反例：quick-start 里深入讲背压语义（属于 streaming.md）。
3. **体裁分类**（按用途，不按路径或标题）：
   - **教程**（01/02 章）：带领读者按顺序完成可观察的结果；必须可照抄运行。
   - **参考**（05 章 + events.md）：在明确范围内支撑查阅，不要求顺序阅读。
   - **原理**（04 章）：解释为什么这样设计；假设读者已会用。
   一篇文档混两种体裁且都很重 → 拆分；轻量次体裁 → 明确标注的小节。
4. **教程递进**：暗自确定起点读者（初学者/中级/高级），每个概念追溯其前置，超前材料后移。

放置成本检查：

- **移动是原子的**：从旧位置删除、在新位置添加、**同一个变更内修复所有入链**（`grep -rn "旧路径" docs/ README.md duo-agent-sdk/README.md`）。
- 手写目录/清单（事件表、配置表）与权威来源（源码、参考篇）重复时，保留一处，其余链接过去。

## 语料审计

结构检查后，用最便宜的探针先：

1. **度量**：`find docs -name "*.md" | xargs wc -l | sort -rn | head -10` 找异常值；超出同类篇幅一倍以上要有明确理由（events.md 作为参考表天然长）。
2. **猎捕思维链泄漏** —— 用 [duo-trim-cot-leakage](../duo-trim-cot-leakage/SKILL.md)：变更叙述、死引用、审查过程记录、流程复述。文档里最常见的形态："如前所述"、审查轮次引用、"本次重构后"。
3. **猎捕重复**：对特征短语 `grep -rn "短语" docs/ README.md`。同一行为说明只留一个家，其余替换为链接。已知易重复点：Builder 配置表（quick-start 与 README 各一份是有意分层，第三份就是重复）、事件时序图（streaming.md 与 events.md 各有用途，架构篇引用不复制）。
4. **数字与代码对账**：测试数、示例数、版本号、API 签名——从源码重新数，不信文档转述（本仓库文档审查曾查出 13 处签名错误、测试数偏差）。
5. **状态三档标注**：功能描述必须落在正确档位——门面可用 / 底层可用需手动组装 / 已定义未接线（对照 limitations.md）。把未接线功能写成可用是 blocker 级错误。

## 验证

- 内部链接：抽查（或全量脚本）每个相对链接指向的文件存在；`docs/` 内链接用相对路径。
- 代码示例：出现在文档中的 Java 片段，其 API 签名对照源码核实（类名、方法名、参数顺序、构造器参数个数）。
- 改了功能描述 → 对应源码行为核对 + 相关测试名核对。

## PR 卫生

文档变更的报告应给出：改了哪些篇、为什么、行数变化、发现并修复的入链。纯文档变更不需要跑测试，但**引用了 API 的示例代码变更**需要 `mvn compile` 级别的核对。
