# 检索电池

针对 [八类泄漏](../SKILL.md#八类泄漏) 的探针。**每个命中都需要语义判断**——电池有意过匹配，也天然欠匹配：每轮清理都有电池漏掉的案例，必须配合对范围内最密集文案的不带模式通读。

## 调用规则

- 加 `--hidden --glob '!.git/**'` 让点目录被搜索；ripgrep 默认跳过隐藏目录。
- 排除项放最后，防止后面的 include 重新放行：`--glob '!target/**' --glob '!logs/**' --glob '!.agents/skills/duo-trim-cot-leakage/**'`（本技能自身引用泄漏原文作校准材料）。
- 自然语言行带 `-i`（句首大写才命中）；匹配代码模式的第一行保持大小写敏感——`-i` 会把 `\bP1\b` 变成噪音。
- 零命中的模式在见过它命中之前证明不了任何事：先对已知的正例字符串测一次，再信任阴性结果。
- 本仓库以中文注释为主，中文电池优先跑。

## 中文电池（主）

```sh
# 死引用与阶段编号
rg -n --hidden '（决策|决策 [0-9一二三]|审查第|审查发现|审查建议|方案 §|阶段 [0-9]|P[0-9] 阶段|（High|（Medium|（Low|（Critical' --glob '*.java' --glob '*.md'

# 变更叙述与版本戳
rg -n --hidden -i '以前|不再|旧版|老的|本次修复|本版|本轮|这次提交|这个提交|此次|原来|先前|之前是'

# 审查过程与对话视角
rg -n --hidden -i '已按|按建议|审查中|如前所述|上一?[轮次]|前面提到|对话中|用户要求'

# 对审查者辩解与含糊措辞
rg -n --hidden -i '是安全的|这样做是对的|应该没问题|应该够|暂时|先这样|姑且|无奈|妥协一下'

# 工作语言残留与分隔符
rg -n --hidden -- '---- ?私有|----+|设计稿|草稿版'
```

## 英文电池（辅，命中英文注释/Javadoc）

```sh
rg -n --hidden '\(decision \d|\(audit [A-Z]\d|\bP-I\b|\bW\d\b|\bT\d\b'
rg -n --hidden -i 'this PR|this commit|this branch|previous commit|used to |no longer|previously|the old '
rg -n --hidden -i 'rejected in review|reviewer|as of v\d|probably |should be enough|it simply|is safe —'
rg -n --hidden -i '\bv1\b|this cut|\bfor now\b|roadmap' --glob '*.java'
rg -n --hidden '§\d'
```

## 已知误报家族

清理中判定过并保留的；以后还会遇到：

- **工具性"用来"** —— "用于签名请求的密钥"（the key used to sign）是工具性格，不是时间格。时间格前面有主语状态（"颜色以前来自…"）。
- **运行时新旧** —— "旧连接排空后新连接接收"命名交接期的存活对象，不是仓库状态。
- **流程文档里的"PR"** —— 描述 PR 工作流本身的文档（提交规范、duo-code-review）合法地说"PR"；禁令针对的是某篇文档采用"某一次 PR"的视角谈代码。
- **`/v1` 协议路径** —— `/v1/chat/completions` 是标识符，不是版本戳。
- **带载体的 §N** —— 外部标准（RFC 9110 §10.1.5、JLS）按节引用合法；§ 禁令只针对未提交的内部草稿。
- **Javadoc 的 @since 版本号** —— 版本化产物的合法标注；被禁的是裸的"本版"戳。
- **备选方案章节** —— 设计文档"备选方案"小节里的"否决"是该体裁的合法归宿，不是审查过程记录。
- **测试名中的 should/when** —— BDD 命名惯例，不是流程复述。
- **docs/ 的"路线图"章节** —— limitations.md 的路线图小节是推迟工作的已提交归宿；被禁的是代码注释里无主的"以后再说"。
